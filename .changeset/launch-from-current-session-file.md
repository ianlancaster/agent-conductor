Start and continue now re-read changed session files before launching, so a session whose `repo:` was just edited starts in the new folder instead of the one from the roster's last poll. While a session's file fails to load or selects an unknown runtime, a start that would launch is refused with the file named instead of launching from the held last-good registration; a running session still answers "already running". Schedules never stop a running session for a fresh-context fire that would be refused, and report such fires, and refused wakes, with the new `refused` schedule event outcome and a warning; a refused `--start-all` launch is logged as a warning too. Session-file change detection now also notices replacements that preserve the mtime, such as `cp -p`, `rsync -a`, or an atomic rename. The agent guide now names the per-runtime `defaultModel` and `defaultEffort` keys that spawns inherit. A pending schedule occurrence is now cancelled by a reload only when its own schedule entry was removed, changed, or paused, so an unrelated session edit no longer cancels a fresh-context restart after it has stopped the session.
