# Work status protocol: design for review

**Scope:** one durable work-status primitive for managed sessions. Agent claims, mechanical liveness, and acceptance remain separate facts. This note proposes behavior; it changes no running fleet.

## One agent tool and the taxonomy

Add a session-only, local-only `report_status` canonical operation. Session identity comes from `/mcp/<codename>`; no caller-supplied session field. Use flat fields so the existing operation schema can validate them without adding a general nested-schema framework:

| Field                                                                   | Rule                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `state`, `work_id`, `summary`                                           | Only unconditional agent inputs. State is `working`, `waiting`, `blocked`, `done`, or `failed`; work ID is a ticket/PR/packet ID or short local slug; summary is a short line.                                                                                                                                                 |
| `waiting_on`                                                            | Required only for `waiting`: named dependency, peer, check, or reviewer.                                                                                                                                                                                                                                                       |
| `needs_from`, `question`, `recommendation`, `meanwhile`, `if_no_answer` | Required only for `blocked`. `needs_from` is `operator` or a named authority; the rest form the decision packet. `if_no_answer` describes the agent's safe default, not a Conductor action.                                                                                                                                    |
| `options`                                                               | Optional bounded list of choices for the blocked decision packet.                                                                                                                                                                                                                                                              |
| `evidence`                                                              | Required nonempty list for `done` identifying the actual output (answer, decision, review, commit, artifact, or check). An artifact revision is optional. This is a claim, never acceptance.                                                                                                                                   |
| `reason`                                                                | Required only for `failed`.                                                                                                                                                                                                                                                                                                    |
| `resolution`                                                            | Required when leaving an unresolved `blocked` claim; briefly says how it was cleared.                                                                                                                                                                                                                                          |
| `attempt_id`, `idempotencyKey`, `mapping_version`                       | Optional for the agent. A packet-supplied attempt ID takes precedence; otherwise Conductor mints one on first `working` and returns it. An idempotency key mirrors `send_to_session`. Conductor stamps mapping version `"1"` from this session's instruction snapshot; an adapter may supply the supported version explicitly. |

`work_id` names one independently reportable unit: a work item **or** a workflow run/node. Parallel nodes use distinct IDs; parent linkage stays with the future Delivery adapter. `mapping_version` is the status vocabulary version, not a plan revision. Persist the version alongside each session's immutable instruction snapshot at launch and stamp its reports from that snapshot, even after a server upgrade; explicit adapter versions must be supported. Export identity as fleet ID plus codename (and recorded run/incarnation), never a bare codename.

Reject fields for the wrong state, mismatched ownership, and `done` without evidence. Persist one current attempt binding per `(fleet, session, work_id)`; a packet ID wins, otherwise mint on first `working`, then reuse across reports and reconnects. Reconnect/resume alone is not a retry. Record the mechanical run/incarnation; a new execution taking over an open attempt needs an explicit operator/dispatch rebind event, not silent minting. A new attempt after disposition is a retry; explicit reports to closed or superseded attempts fail. A `done` claim awaiting acceptance remains bound **only** for `done` amendments with new evidence. Accepted and failed attempts cannot reopen. Reject `working` on B while the session still claims `working` on A. Every state change on an open attempt is accepted. Same-state reports require changed `waiting_on`, a blocked clarification of the same question and authority, a new question, or new `done` evidence. New questions resolve the old blocker and start a new revision; new evidence starts a completion-claim revision. Reject summary-only `working` or `waiting` updates. Same-state changes preserve state-entry time, work age, cumulative intervals, and stale clock; only a new blocker gets a new blocker age. Exact duplicates return the prior receipt with `unchanged: true` and write an `unchanged_report` audit event without changing status. A keyed retry returns its original receipt even after a later transition; key reuse with different content fails. Receipts include attempt ID, applicable blocker ID/revision, stable event ID, sequence, and server time. `report_status` changes no health, pause, dispatch, or authority.

Bob's wider categories map as follows:

| Category                                                  | Source in this slice                                                                                                                                                                                                                                   |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `working`, `waiting`, `blocked`, `done-claimed`, `failed` | Agent transition. `done` maps to displayed `done-claimed`.                                                                                                                                                                                             |
| `queued`                                                  | Assignment/dispatch authority, only when an actual work assignment exists; an unstarted configured session is **not** a queued work item.                                                                                                              |
| `in-review`                                               | Derived only from authoritative review or PR evidence in a later integration; until then show `done awaiting acceptance`. Waiting for an agent reviewer can use `waiting_on`; asking the operator for review is `blocked` with `needs_from: operator`. |
| `accepted`                                                | Separate evidence-backed event from the operator or a configured session acceptance authority.                                                                                                                                                         |
| `paused`                                                  | Existing session pause is an automation/delivery overlay, not a work hold; it does not rewrite the claim or remove work from WIP. Explicit work holds are deferred.                                                                                    |
| `stale`, `disagreement`, `resolved`                       | Derived display/annotation, never agent states. `abandoned` is a future authority-set terminal outcome.                                                                                                                                                |

## Durable facts and derivation

Add an append-only `work_status_events` table through a new migration in `src/store/index.ts`, in the resolved fleet data directory's `conductor.db`. Each row has a stable fleet-qualified event ID, monotonically increasing sequence, server time, event kind, mechanical actor/execution identity, work ID, attempt ID, mapping version, optional idempotency key, and bounded payload. Claim rows distinguish transition from same-state revision; other kinds cover ignored duplicates, blocker open/revision/resolution, accepted/not-accepted, work closure, and trusted attempt rebind. Index attempt history and open blockers. Apply reports serially per attempt in one transaction; persistence failure changes no status. Arrival sequence is **not** causal order: keyed retries return their original receipt after later reports, and closed/superseded attempts reject new reports, but this slice has no general causality or expected-revision precondition machinery. Rebuild projections after restart. `session_state`, `health_log`, and the optional best-effort `event_journal` are not sources of work truth. Subscribers are hints only. Provide an **internal**, bounded read-after-sequence query with scoped fleet/session identity, stable IDs, and a high-water mark so a future adapter can recover missed notifications; do not expose a Delivery consumer yet. Old sessions show `unreported` until a claim.

Time in state runs from state entry; work age runs from its **first** attempt, through retries. Same-state revisions change neither. Show active-attempt and distinct active-unit WIP (`working`, `waiting`, `blocked`, `done-claimed`) plus total **started but unresolved** units, including failed attempts awaiting disposition. Session pause removes none of these; it remains a visible overlay. Acceptance closes work; an operator work-closure event with reason can close abandoned/failed work. Do not combine parent work items and their node units into one throughput total.

Mint a `blocker_id` when blocked opens and increment its revision when a changed question replaces it; keep the ID/revision for clarifications of the same request. `resolve_status_blocker` must target the exact blocker ID and revision, rejecting a late answer to a replaced question. An agent transition can resolve its open blocker with the required resolution note. An operator answer records its actor and evidence and enters the ordinary **protected delivery queue** for the owning session; queue admission and resolution must be atomic or recoverable. A failed live delivery leaves the answer durably pending for retry. Deliver to a live session, hold for explicit restart if stopped, and never auto-start. Delivery is separate from the agent's acknowledgement, which is its next transition. Show `resolved; awaiting agent transition` and move it to attention after the waiting threshold.

Starting defaults: `disagreement` after **1 hour** of positive idle evidence for a `working` claim (or fresh proof its process stopped); `stale` when that claim is **4 hours** old with positive nonactivity covering its last hour; overdue `waiting` and resolved-awaiting-transition after **4 hours**; `blocked` immediately. Tune durations from the pilot. Show the threshold and observation behind each badge. Derive telemetry freshness from three health beats; missing or inconclusive evidence is `unknown`, never idle/stale. Same-state reports do not refresh claim age or stale clocks. No timers write work events. Derived badges never drive restart, redispatch, or automatic recovery; existing health/sentinel policy stays independent, and no new paging policy is added.

## Window, resolution, and acceptance

Extend the canonical `/status` report and `get_session_status` JSON, then let the existing live window render it. Show one row per latest work attempt with **session, work ID, attempt, claim/display state, time in state, total age, last evidence, needs from, liveness**, plus WIP and **“on Ian: N, oldest <age>”** summaries. Order: (1) blocked on operator, oldest first, then other authorities' open blockers; (2) stale **or disagreement** as soon as each qualifies; (3) waiting past threshold and overdue resolved-awaiting-transition; (4) done awaiting acceptance; (5) working; (6) queued. Keep failed-awaiting-disposition and other rows visible separately. Within bands, sort oldest first, then work/attempt ID. Keep existing fleet facts. Unknown telemetry does not hide an open blocker. Agents send operator decision packets through the existing `send_to_operator` path too; this window is Ian's durable queue, without new paging.

Acceptance is a separate local-only `record_status_acceptance(work_id, attempt_id, done_claim_event_id, evidence, artifact_revision?)` operation. The exact done claim must still be current; when it cites an artifact revision, acceptance must target that revision too. A superseded claim fails. Record the mechanically identified actor, time, contract reference if supplied, and evidence as **attested** rather than Conductor-verified. The operator may accept; a session authority may accept only work from target sessions listed for it in strict `status.acceptanceAuthorities` configuration (default `{}`), never its own attempt. Contract-level scopes and automated PR/CI verification are deferred. Ian uses `/accept-status <work-id> [evidence-ref]` and `/reject-status <work-id> <reason>` in the console or `conductor cmd`; authority MCP/adapters use the full exact-target form. Add `record_status_not_accepted` with exact claim ID and required reason before a new `working` attempt so done→working reads as rework. Deliver rejection reasons through protected messaging. Accepted or failed attempts cannot reopen.

Ian uses `/resolve <work-id> <answer>` for a direct window reply; ordinary replies followed by the agent's own transition remain valid. Each short command resolves and binds the unique current done claim or blocker **once at operation start**, names its event ID/revision/evidence in the receipt, and checks that exact target at commit. If it changed, fail without selecting a replacement. If the work ID has open attempts in multiple sessions, reject as ambiguous and request an attempt ID. No confirmation round trip is added.

Agent-facing protocol addition, aligned with `~/Projects/cognitive-agent-v2/parts/protocol.md` §Status at `ec59fd4`: “Report with `report_status` when your state changes. Send `state`, `work_id`, a short `summary`, and the fields required for that state. Before ending a turn to await a peer, background task, or CI that may take more than an hour, report `waiting` and name it. An operator review or decision is `blocked` with `needs_from: operator`; send the decision packet to the operator too. Work on one `working` item at a time. Never report on a timer or to narrate the next step; keep that in your plan. `done` is a claim, and a report grants no authority.” The tool description lists conditional fields, optional attempt/key, snapshot-derived mapping version, and narrow same-state corrections without inviting progress narration; `docs/agent-guide.md` explains those mechanics and `/tag` remains separate.

## Verification and limits

Focused tests, then the full quality gate when implementation is approved:

- Schema and MCP identity: conditional fields/options, snapshot-stamped vocabulary version, fleet-qualified export identity, one independently reportable node ID per parallel node, and operator/authority/CLI scope parity.
- Attempt binding: omitted ID reused after restart/reconnect; packet ID precedence; explicit trusted rebind; one working claim per session; failed/accepted/closed/superseded attempts reject new reports; a new attempt after rejection preserves first-start work age.
- Journal ordering: serial concurrent reports in one transaction; same-state waiting/blocker/done revisions preserve age; summary-only working/waiting rejected; exact duplicate gives `unchanged`; an old keyed retry after a newer transition returns its original receipt without reapplying; no claim of arbitrary unkeyed causal ordering.
- Blockers: same-question clarification keeps ID, new question advances revision and resets only blocker age, a late answer to the old revision fails; live answer delivery, stopped-session hold, failed live delivery retained durably, and agent acknowledgement remains a later transition.
- Acceptance and short commands: non-SHA done evidence identifies an answer/review; acceptance targets current done event and its artifact revision only when present. Test self-acceptance, unrelated scope, superseded claim/revision, amended done evidence without reopening, accepted/failed amendment rejection, and not-accepted rework. Test short-command target binding/receipt, a target changing before commit, ambiguous work IDs, and no confirmation round trip.
- Projection and surface: pause leaves WIP intact while operator conversation continues, failed work remains started/unresolved until new attempt or closure, parent/node counts stay separate; disagreement enters band 2 before four hours, waiting/resolved thresholds and Ian's queue age sort correctly; missing telemetry stays unknown. Exercise read-after-sequence/high-water catch-up and restart recovery with temporary SQLite, fake time, HTTP MCP, `/status`, and the live window. Pin the tool description and injected protocol against the stem-cell transitions-only rule.

First slice excludes custom categories, PR/CI polling, automatic acceptance, Delivery ingestion, cross-fleet routing, contract-level authority scopes, general causal preconditions, explicit work holds, workflow critical-path inference, historical tag conversion, throughput charts, WIP enforcement, pages for aged items, and any restart, revive, or redispatch behavior.
